# FashionStore

یک پروژهٔ فروشگاه اینترنتی پوشاک که API آن با ASP.NET Core Web API و ‎.NET 8‎ پیاده‌سازی شده است. برنامه از SQLite برای ذخیره‌سازی اطلاعات استفاده می‌کند، احراز هویت کاربران با ASP.NET Core Identity و JWT انجام می‌شود و Swagger برای مشاهده و آزمایش API در محیط توسعه فعال است.

این مخزن شامل وب‌اپلیکیشن/API، تست‌های واحد و یک ابزار موقت برای مشاهدهٔ داده‌های SQLite است. رابط وب MVC موجود، قالب اولیهٔ ASP.NET Core است؛ جریان اصلی خرید از طریق API انجام می‌شود و یک فرانت‌اند جداگانه می‌تواند به API متصل شود.

## قابلیت‌های فعلی

- ثبت‌نام، ورود و دریافت اطلاعات کاربر با توکن JWT
- نمایش محصولات فعال و جست‌وجو بر اساس نام یا توضیحات
- فیلتر محصولات بر اساس دسته‌بندی و مشاهدهٔ جزئیات، تصاویر و تنوع‌های محصول
- ایجاد محصول با تنوع‌هایی مانند اندازه، رنگ، SKU، قیمت و موجودی
- مشاهده و مدیریت اقلام سبد خرید کاربر واردشده
- ثبت نشانی، ثبت سفارش از سبد و مشاهدهٔ سفارش‌ها
- بررسی موجودی هنگام افزودن کالا و نهایی‌کردن سفارش و کم‌کردن موجودی هنگام خرید
- مهاجرت خودکار پایگاه داده و درج داده‌های نمونه هنگام راه‌اندازی
- مستندات تعاملی API با Swagger در محیط Development

## فناوری‌ها

- ‎.NET 8 / ASP.NET Core MVC و Web API‎
- Entity Framework Core 8 و SQLite
- ASP.NET Core Identity و JWT Bearer Authentication
- Swagger / Swashbuckle
- xUnit و EF Core InMemory برای تست‌ها

## اجرا در ویندوز

از ریشهٔ مخزن اجرا کنید:

```powershell
dotnet restore .\FashionStore.sln
dotnet run --project .\FashionStore.Web\FashionStore.Web.csproj --launch-profile http
```

سپس Swagger را باز کنید:

```text
http://localhost:5022/swagger
```

برای اجرای پروفایل HTTPS:

```powershell
dotnet run --project .\FashionStore.Web\FashionStore.Web.csproj --launch-profile https
```

پروفایل HTTPS روی `https://localhost:7286` و نیز `http://localhost:5022` گوش می‌دهد. در صورت هشدار گواهی توسعه، گواهی HTTPS توسعهٔ .NET را اعتمادسازی کنید یا برای کار محلی از پروفایل `http` استفاده کنید. با `Ctrl+C` سرور متوقف می‌شود.

برنامه از رشتهٔ اتصال `DefaultConnection` در `FashionStore.Web/appsettings.json` استفاده می‌کند. مقدار فعلی `Data Source=FashionStore.db` است؛ فایل پایگاه داده در مسیر کاری اجرای برنامه ساخته یا استفاده می‌شود. هنگام راه‌اندازی، مهاجرت‌های EF Core اعمال می‌شوند و اگر داده‌ها وجود نداشته باشند، دسته‌بندی‌های نمونه، چند محصول و یک حساب مدیر اولیه درج می‌شوند.

### داده‌های نمونه و حساب مدیر اولیه

در نصب تازه، داده‌های نمونه شامل دسته‌بندی‌های `Men`، `Women`، `Kids` و `Accessories` و چند محصول نمونه است. حساب مدیر اولیه در کد seed چنین است:

```text
Email:    admin@fashionstore.com
Password: Admin@123
```

این اطلاعات فقط برای محیط محلی/آزمایشی مناسب‌اند. در استقرار واقعی باید ایجاد حساب اولیه و مقادیر محرمانه از تنظیمات امن و فرایند استقرار کنترل شوند. همچنین در کد فعلی مجوز Admin برای ساخت محصول الزام نشده است؛ هر کاربر واردشده می‌تواند به آن endpoint دسترسی داشته باشد.

## مستندات و شمار APIها

در حال حاضر **۱۲ endpoint با متد و مسیر مشخص** تعریف شده‌اند. Swagger نیز به‌طور خودکار از کنترلرها تولید می‌شود. شمارش مسیرها:

### احراز هویت — `Auth`

| متد | مسیر | نیاز به توکن | توضیح |
|---|---|---:|---|
| `POST` | `/api/Auth/register` | خیر | ثبت‌نام و دریافت JWT |
| `POST` | `/api/Auth/login` | خیر | ورود و دریافت JWT |
| `GET` | `/api/Auth/me` | بله | دریافت پروفایل کاربر جاری |

### کاتالوگ — `Catalog`

| متد | مسیر | نیاز به توکن | توضیح |
|---|---|---:|---|
| `GET` | `/api/Catalog/products` | خیر | فهرست محصولات؛ فیلتر اختیاری با `search` و `categoryId` |
| `GET` | `/api/Catalog/products/{productId}` | خیر | جزئیات محصول، تصاویر و تنوع‌ها |
| `POST` | `/api/Catalog/products` | بله | ایجاد محصول به‌همراه تنوع و تصویر |
| `GET` | `/api/Catalog/categories` | خیر | فهرست دسته‌بندی‌ها |

نمونهٔ جست‌وجو و فیلتر:

```text
GET /api/Catalog/products?search=cotton
GET /api/Catalog/products?categoryId=00000000-0000-0000-0000-000000000000
```

### سبد خرید — `Cart`

تمام مسیرهای این گروه به JWT نیاز دارند.

| متد | مسیر | توضیح |
|---|---|---|
| `GET` | `/api/Cart` | دریافت سبد خرید کاربر واردشده |
| `POST` | `/api/Cart/items` | افزودن تعداد مشخصی از یک تنوع محصول |
| `DELETE` | `/api/Cart/items/{cartItemId}` | حذف یک قلم از سبد |

نمونهٔ بدنهٔ افزودن به سبد:

```json
{
  "productVariantId": "شناسهٔ تنوع محصول از جزئیات محصول",
  "quantity": 2
}
```

در هر درخواست افزودن، تعداد ارسالی به تعداد قبلی همان تنوع اضافه می‌شود. کم‌کردن یا جایگزین‌کردن مستقیم تعداد فعلاً endpoint جداگانه ندارد.

### سفارش و نشانی — `Order`

تمام مسیرهای این گروه به JWT نیاز دارند.

| متد | مسیر | توضیح |
|---|---|---|
| `GET` | `/api/Order` | دریافت سفارش‌های کاربر جاری |
| `POST` | `/api/Order/address` | ثبت نشانی برای کاربر جاری |
| `POST` | `/api/Order/checkout` | ثبت سفارش بر اساس سبد و نشانی انتخاب‌شده |

نمونهٔ بدنهٔ نشانی:

```json
{
  "street": "خیابان نمونه، پلاک ۱۰",
  "city": "تهران",
  "state": "تهران",
  "postalCode": "1234567890",
  "country": "ایران"
}
```

نمونهٔ بدنهٔ نهایی‌کردن سفارش:

```json
{
  "addressId": "شناسهٔ نشانی ثبت‌شده برای همین کاربر",
  "notes": "تحویل در ساعات اداری"
}
```

در منطق فعلی، هزینهٔ ارسال برای سبد غیرخالی `15` واحد پولی ثابت است. واحد پول در مدل/تنظیمات مشخص نشده است؛ بنابراین فرانت‌اند نباید بدون هماهنگی آن را تومان یا ریال فرض کند.

## استفاده از Swagger و احراز هویت

1. برنامه را در `Development` اجرا کنید و صفحهٔ `/swagger` را باز کنید.
2. برای ثبت‌نام، `POST /api/Auth/register` را با `firstName`، `lastName`، `email` و `password` اجرا کنید؛ یا از `POST /api/Auth/login` استفاده کنید.
3. مقدار `token` را از پاسخ بردارید.
4. دکمهٔ **Authorize** را در Swagger بزنید و توکن JWT را وارد کنید. اگر رابط مقدار خام می‌پذیرد همان توکن را بگذارید؛ در صورت نیاز رابط، پیشوند `Bearer` را مطابق راهنمای همان پنجره اضافه کنید.
5. حالا endpointهای محافظت‌شده را اجرا کنید.

در درخواست‌های فرانت‌اند هدر زیر ارسال می‌شود:

```http
Authorization: Bearer <JWT>
Content-Type: application/json
```

توکن‌های فعلی شش ساعت اعتبار دارند. ثبت‌نام و ورود، پاسخ شامل `token`، ایمیل، نام و `expiresAt` می‌دهند.

### جریان پیشنهادی خرید از فرانت‌اند

1. با `GET /api/Catalog/categories` دسته‌بندی‌ها و با `GET /api/Catalog/products` کاتالوگ را بخوانید.
2. با `GET /api/Catalog/products/{productId}` جزئیات، تنوع‌ها و شناسهٔ هر تنوع را بگیرید.
3. کاربر را با register یا login وارد کنید و JWT را برای درخواست‌های بعدی نگه دارید.
4. با `POST /api/Cart/items` تنوع و تعداد را به سبد اضافه کنید و با `GET /api/Cart` سبد را نمایش دهید.
5. نشانی را با `POST /api/Order/address` ثبت کنید.
6. با شناسهٔ نشانی، `POST /api/Order/checkout` را فراخوانی کنید.
7. سفارش‌های بعدی را با `GET /api/Order` بخوانید.

## اتصال فرانت‌اند و CORS

آدرس API برای پروفایل HTTP محلی:

```text
http://localhost:5022
```

اگر فرانت‌اند روی origin دیگری (مثلاً `http://localhost:3000` یا `http://localhost:5173`) اجرا شود، مرورگر درخواست‌های cross-origin را می‌فرستد. در کد فعلی سیاست CORS ثبت نشده است؛ برای اتصال مستقیم مرورگری، origin دقیق فرانت‌اند باید در سرور مجاز شود. در استقرار، فقط دامنه‌های واقعی فرانت‌اند را مجاز کنید. همچنین اگر صفحهٔ فرانت‌اند HTTPS باشد، بهتر است API هم HTTPS باشد.

## مدل داده در یک نگاه

- **کاربر**: اطلاعات Identity، فعال/غیرفعال بودن، نشانی‌ها، سبد و سفارش‌ها
- **دسته‌بندی**: نام و توضیحات
- **محصول**: نام، slug، توضیحات، دسته‌بندی و وضعیت نمایش
- **تنوع محصول**: اندازه، رنگ، SKU، قیمت، موجودی و وضعیت فعال
- **تصویر محصول**: URL تصویر و مشخص‌کردن تصویر اصلی
- **سبد و اقلام سبد**: متعلق به کاربر و شامل تنوع محصول و تعداد
- **نشانی**: اطلاعات تحویل متعلق به کاربر
- **سفارش و اقلام سفارش**: مبلغ‌ها، وضعیت و تصویر ثابت از نام/قیمت اقلام در زمان سفارش

پایگاه داده با EF Core و migrationهای پوشهٔ `FashionStore.Web/Data/Migrations` مدیریت می‌شود.


## وضعیت فعلی و مواردی که هنوز پیاده‌سازی نشده‌اند

- endpoint ویرایش/حذف محصول یا مدیریت دسته‌بندی وجود ندارد.
- endpoint جداگانه برای کاهش یا تنظیم تعداد اقلام سبد وجود ندارد.
- پرداخت آنلاین و ثبت/تأیید تراکنش وجود ندارد؛ checkout فعلی سفارش را با وضعیت `Pending` ثبت می‌کند.
- مدیریت سفارش برای مدیر (تغییر وضعیت، لغو یا بازپرداخت) وجود ندارد.
- endpoint جداگانه برای فهرست نشانی‌های ذخیره‌شده، ویرایش یا حذف نشانی تعریف نشده است. پروفایل `GET /api/Auth/me` در کنترلر، فقط اطلاعات پایهٔ کاربر را برمی‌گرداند.
- صفحه‌بندی، مرتب‌سازی، فیلتر قیمت/اندازه/رنگ و تخفیف در API فعلی پیاده نشده‌اند.
- آپلود فایل تصویر وجود ندارد؛ ایجاد محصول URL تصویر می‌گیرد.
- سیاست CORS در برنامه تعریف نشده است.
- endpoint ساخت محصول با `[Authorize]` محافظت شده، اما بررسی نقش Admin ندارد.
- Swagger فقط وقتی `ASPNETCORE_ENVIRONMENT=Development` باشد فعال می‌شود.
- کلید JWT و حساب seed فعلی برای توسعه‌اند و باید پیش از انتشار عمومی با مقادیر امن و فرایند مناسب جایگزین شوند.

## پیشنهاد برای توسعهٔ آینده

### اولویت بالا برای آماده‌شدن فرانت‌اند

1. افزودن CORS محدود به originهای توسعه و تولید فرانت‌اند.
2. اصلاح کنترل دسترسی کاتالوگ: محدودکردن ساخت/ویرایش/حذف محصول به نقش مدیر، و محافظت از endpointهای مدیریتی دسته‌بندی.
3. افزودن endpoint تغییر تعداد سبد، فهرست/ویرایش/حذف نشانی‌ها و پاسخ کامل پروفایل شامل نشانی‌ها.
4. مستندسازی قرارداد API شامل نمونهٔ پاسخ‌ها، خطاها، واحد قیمت و قواعد اعتبارسنجی؛ سپس تولید/انتشار OpenAPI برای فرانت‌اند.

### اولویت بالا برای فروش واقعی

1. اتصال درگاه پرداخت و نگه‌داشتن سفارش تا تأیید امن callback پرداخت.
2. پیاده‌سازی لغو سفارش، تغییر وضعیت، استرداد و تاریخچهٔ وضعیت سفارش.
3. کنترل هم‌زمانی موجودی در checkout با تراکنش پایگاه داده تا فروش بیش از موجودی رخ ندهد.
4. تعیین واحد پول، محاسبهٔ پیکربندی‌پذیر هزینهٔ ارسال و افزودن مالیات/تخفیف در صورت نیاز کسب‌وکار.

### بهبودهای تجربهٔ کاربر و کاتالوگ

- صفحه‌بندی، مرتب‌سازی و فیلتر بر اساس بازهٔ قیمت، اندازه، رنگ و موجودی
- افزودن علاقه‌مندی‌ها، امتیاز و نظر کاربران
- کد تخفیف، کمپین و قیمت‌گذاری زمان‌دار
- تصاویر با آپلود امن به فضای ذخیره‌سازی و تولید thumbnail
- اعلان ایمیل/SMS برای ثبت سفارش و تغییر وضعیت
- سبد مهمان و ادغام آن با سبد حساب پس از ورود
- پشتیبانی از چندزبانگی و چندارزی در صورت نیاز

### بهبودهای فنی و عملیاتی

- انتقال کلید JWT و اطلاعات حساس از `appsettings.json` به Secret Manager یا متغیرهای محیطی
- مدیریت نقش‌ها و مجوزها به‌صورت دقیق، محدودسازی نرخ درخواست ورود و سیاست رمز عبور مناسب
- ثبت لاگ ساختاریافته، health check، مانیتورینگ و مدیریت خطا با پاسخ‌های یکپارچه
- افزودن تست‌های API/یکپارچه برای ثبت‌نام، مجوزها، موجودی، checkout و خطاها
- استفاده از CI برای build و اجرای تست‌ها و آماده‌سازی استقرار
- برنامهٔ backup و نگه‌داری پایگاه داده؛ انتخاب پایگاه دادهٔ سروری در صورت رشد ترافیک

## نکتهٔ امنیتی

مقادیر `Jwt:Key` و رمز حساب نمونه در تنظیمات/کد فعلی برای اجرای توسعه قرار گرفته‌اند. آن‌ها را secret تولیدی تلقی نکنید و با اطلاعات واقعی در مخزن جایگزین نکنید. در محیط واقعی از HTTPS، secretهای خارج از سورس، مجوزهای مبتنی بر نقش و CORS محدود استفاده کنید.
